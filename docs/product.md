# Project Desk: текущий продукт

Команды ведут проекты: в каждом есть руководитель, участники, задачи и
обсуждения. Руководитель отвечает за ход проекта, но не обязательно является
исполнителем каждой задачи. Одному человеку могут быть доступны несколько
проектов. Сейчас задачи и комментарии просматривают внутри отдельного проекта.

Задача имеет название, описание, исполнителя (может отсутствовать), статус,
необязательный срок и признак «Нужен руководитель». Статусы: открыта, в работе,
заблокирована, готово. «Заблокирована» означает наличие препятствия; его
содержание команда описывает в задаче или комментариях. Формального процесса
эскалации в продукте раньше не было; теперь его роль играет признак «Нужен
руководитель» — см. ниже.

Все участники могут читать и изменять задачи своего активного проекта.
Обсуждение задачи ведётся в карточке: любой участник активного проекта
добавляет комментарий, автор подставляется из выбранного демо-пользователя.
Задача без исполнителя — общая: её видит только руководитель проекта, поэтому
счётчики в переключателе проектов совпадают с числом строк в списке.
Чужие проекты и задачи не выдаются API. Архивный проект хранит историю
и не принимает изменения. Управления участниками и проектами в UI пока нет;
это фиксированная конфигурация демо. Вход заменён явным выбором демо-пользователя.

## Признак «Нужен руководитель»

Чтобы руководитель видел, где нужно его участие, задача может нести признак
«Нужен руководитель» (`escalated`). Исполнитель ставит его в карточке задачи,
когда для решения не хватает его полномочий: согласование, приоритет, доступ.
Признак независим от статуса: задача может быть открыта, в работе или
заблокирована. Завершённая задача признак не несёт — при закрытии флага
снимается, а передать его вместе с `done` нельзя.

Руководителю активного проекта (`owner_id` совпадает с пользователем, проект
не в архиве) приложение показывает:

- оранжевый счётчик в переключателе проектов — число незавершённых задач
  с признаком; у остальных участников счётчик равен нулю;
- в списке задач такие задачи идут первыми и выделены цветом и меткой;
- при запуске открывается проект с наибольшим числом таких задач, чтобы
  не обходить каждый проект вручную.

Остальные участники видят задачи и порядок, но эскалации остаются в контексте
проекта; отдельной очереди «все мои эскалации» пока нет.

В наборе есть проекты клиентского портала, отчётности, базы знаний, архивный
вебинар и отдельный проект аналитика. Пользователи и обсуждения вымышлены.
Даты и сроки — UTC. При первом запуске сроки привязываются к дате создания
БД; после этого они не сдвигаются. Кнопки «обновить демо» в приложении нет.

Данные показывают текущее состояние задач и историю обсуждений. Потребность
и контекст самостоятельного задания приведены в `task_v7.md`. Неопределённости
разрешайте обоснованными допущениями с описанием их влияния в итоговом отчёте.
